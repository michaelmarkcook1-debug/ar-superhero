Prepared 7 November 2026, Mauritius time (UTC+4).

No remote push, merge or deployment has been performed. The deployed application has not been independently verified. Merge and deployment each require Mike's explicit approval of the exact proposed action.

## 1. Honest upload demonstration

- Real-file selection is removed from the shared demonstration panel. Dropped files are rejected without reading their content or creating a result.
- The only creation action is **Show sample entry**. It uses a fictional filename, records a **Demo sample**, and explicitly reports that no analysis occurred.
- Fake progress, fabricated file sizes, source-traced branding and claims of completed audits are removed from that flow.
- The Direct and Enable document libraries identify all their sample rows, signals and states as fictional. The linked decision-model explanation identifies its impacts as examples.
- The separate RFP/RFI uploader, AG API client, routes, credentials and integration components are unchanged by this commit.

Files: `client/src/components/cockpit/upload.tsx`, `client/src/pages/Direct.tsx`, `client/src/pages/Enable.tsx`, `client/src/lib/cockpit.ts`, `tests/upload-demo.mjs`.

Acceptance checks passed: real drops rejected before and after sample creation; no real filename added; no file selector; keyboard sample action; material-type selection; reset and repeat; demo labels on existing and new rows; no API calls caused by demo actions; separate RFP/RFI file input retained. Tested Direct and Enable at 1440px and 390px. The browser tests stub API responses and do not establish live integration health.

## 2. Stakeholder deck intelligence

- The existing persona and deck-type selectors are preserved. A shared decision brief ranks available evidence against both selections and states the specific decision the audience should make.
- Three priorities lead the deck. Each separates **What AG reports** from **What you should decide**, with source references. Guidance is deterministic and labelled as recommendations, not generated facts or predictions.
- Scenario decks now draw on the existing persona briefing reader as well as the AG brief: provider comparisons, AI readiness, reported revenue, reputation, narrative/reality divergences and channels, reported workforce fields, and captured movements where available. Existing placements and coverage sections remain in their established deck types.
- Scenario decks include an appendix of the supported evidence considered, rather than silently dropping signals outside the top three. This is the data exposed through the current integrations, not a claim to have audited every dataset in AnalystGenius.
- AG's existing slide kit, logo, Inter typography, violet/ink palette and footer remain the design authority. Covers use persona-relevant metrics.
- Missing scores no longer become chart zeros. Incomplete peer pairs are excluded and labelled. Default peer selections propagate to placement lookups. Quarterly placement windows start at the calendar-quarter boundary.
- Unavailable/degraded AG reads cannot populate the cover or decision brief. Stale reads carry their observation date. Failed revenue/workforce responses are rejected. Missing revenue no longer implies private ownership; unsupported recognition forecasts are removed.

Files: `server/services/directPersonaDeck.ts`, `server/services/scenarioDeck.ts`, `server/services/personaBriefing.ts`, new `server/services/stakeholderDeckInsight.ts`, new `server/services/stakeholderDeckSlides.ts`, `tests/stakeholder-decks.mjs`.

## Limitations and rollback

No AG credentials are configured in this checkout. Current live payloads, upstream field provenance and deployed behaviour remain unverified. Workforce fields use the existing reported-field reader; this change does not certify that upstream dataset. Recommendations do not replace judgement or validate client-proof reuse rights.

Scenario generation now reads workforce context for the selected peer set, which may add API latency. More supporting evidence can increase deck length. There are no database migrations, new categories, new selectors or credential changes.

The changes are split into one upload commit and one deck commit. Reverting either restores its previous behaviour without a data migration. Reverting the upload commit would restore the original misleading demo flow.
